# Muscle Atlas — Realistic Human Illustration Style Contract

기준일: 2026-10-02  
상태: **LOCKED / MUST FOLLOW**  
정본 branch: `preview/development`

## 1. 공통 원칙

Muscle Atlas의 다음 두 교육영역은 최종 자산에서 **실제 사람처럼 보이는 실사형 의료교육 일러스트**를 기본 스타일로 사용한다.

1. 환자교육용 스트레칭·강화운동
2. Physical Examination / 진찰검사

막대인간, 단순 기호형 SVG, 지나치게 추상화된 인체도해는 최종품으로 사용하지 않는다. 기존 개념형 SVG는 migration/fallback 및 자동 QA용 임시자산으로만 유지할 수 있다.

## 2. 환자교육용 운동 일러스트

- 문틀 스트레칭, 경추 스트레칭 등에서 승인된 **실제 사람처럼 보이는 실사형 교육 일러스트**를 스타일 기준으로 삼는다.
- 시작자세 / 끝자세가 한눈에 구분되어야 한다.
- 동일 인물·동일 복장·동일 시점의 연속성을 유지한다.
- 움직임 방향, 지지점, 주의점, 흔한 보상동작을 필요한 범위에서 시각적으로 표시한다.
- 환자가 혼자 보고 따라 할 수 있는 수준이어야 한다.
- 모바일/PC/A4 인쇄에서 모두 가독성이 유지되어야 한다.

## 3. Physical Examination 일러스트

Physical Examination도 별도의 단순 도식 스타일을 사용하지 않고 **같은 실사형 인체 표현 계열**을 사용한다.

필수 요소:
- 실제 사람처럼 보이는 환자
- 실제 사람처럼 보이는 검사자
- 정확한 환자 시작자세
- 검사자 손 위치
- 힘/스트레스 방향
- 관절·근육·인대의 검사 방향
- 양성 소견 위치
- 필요 시 흔한 오류 / 안전 주의점

Physical Examination에서는 실사형 인물 위에 교육용 overlay를 추가한다.
- 화살표
- 손 위치 강조
- 힘 방향
- 통증/양성 위치
- 위험한 provocation 금지 표시

즉, **실사형 인체 + 검사정보 overlay**가 정본 스타일이다.

## 4. 품질 기준

- 해부학적으로 잘못된 자세 금지
- 검사자 손 위치·힘 방향 오류 금지
- 관절 가동범위 과장 금지
- 실제 임상에서 쓰기 어려운 포즈 금지
- 환자교육용과 의료진 교육용의 목적 차이는 유지하되, 인체 표현 스타일은 통일
- 특정 교과서/사진의 직접 복제·트레이싱 금지
- Stable ID별 자산 registry와 검수상태를 유지

## 5. 현재 EXAM-001과의 관계

148개 진찰검사 Stable-ID 맞춤도해 baseline은 **2026-10-02 기준 148/148 COMPLETE**다. 이 baseline은 구조·내용·힘 방향의 정본이며, EXAM-REAL-001 실사형 승격에서 각 후보의 임상 정확도 기준으로 계속 보존한다.

그 후 최종 시각자산은 순차적으로:
`개념형/구조도해 → 실사형 Physical Examination 일러스트`
로 승격한다.

현재 baseline 맞춤도해를 “최종 실사형 완성품”으로 오기하지 않는다.

## 6. 완료 Gate

Physical Examination 최종 승격 시:
- 실사형 환자/검사자 표현
- 손 위치·힘 방향 정확성
- 3단계 시작/시행/양성 판단
- 모바일/PC visual QA
- 사용자 Preview 확인
를 모두 통과해야 한다.

환자교육 운동 최종 승격 시:
- 실사형 인체
- 자세 정확성
- 시작/끝 동작 연속성
- 텍스트 안전성
- 모바일/PC/A4 QA
- 사용자 Preview 확인
을 모두 통과해야 한다.


## 7. 인물 캐스팅 정본

환자/검사자의 남성형·여성형 표현은 임의로 정하지 않는다.

정본:
`docs/REALISTIC_HUMAN_MODEL_CASTING_CONTRACT.md`

새 자산은 해당 문서의 균형 배정 규칙을 따른다. 이미 승인된 자산은 캐스팅 규칙만 맞추기 위해 재생성하지 않는다.

## 8. 개발용 검수 문구와 최종 사용자 화면

개발 중에는 후보/승인상태를 구분하기 위해 최소한의 Preview 상태문구를 둘 수 있다.

하지만 최종 사용자 화면에서는 다음과 같은 개발 운영 문구를 제거하거나 숨긴다.
- Preview 후보
- 승인 전
- 반영 대기
- canonical 교체 여부
- 기존 schematic fallback 유지 여부
- 내부 검수 PASS/FAIL 문구
- gen_id 등 개발 식별자

최종 화면에는 실제 교육에 필요한 제목, 검사법, 임상 해석, 안전정보만 남긴다.

후보 선정·사용자 수정지시·승인·폐기 이력은 화면이 아니라 GitHub/IP Vault provenance에 보존한다.


## 9. 사용자 시각교정 재발방지 규칙 — LOCKED 2026-10-04

Babinski 자극경로 교정에서 발생한 반복 실패를 재발시키지 않기 위해 다음 순서를 모든 Physical Examination 및 환자교육 실사형 자산 수정에 강제한다.

1. **해부학 landmark를 먼저 잠근다.**
   - 화면의 왼쪽/오른쪽을 임상 방향으로 사용하지 않는다.
   - medial/lateral, proximal/distal, radial/ulnar, tibial/fibular 등은 해부학적 구조로 표현한다.
   - 예: Babinski의 외측은 `lateral heel → lateral plantar border → fifth-toe side`로 고정한다.

2. **사용자가 직접 그린 선·원·화살표·동그라미는 최우선 spatial constraint다.**
   - 사용자가 이미지 위에 직접 표시한 경로가 있으면 문장 설명을 다시 추론해서 위치를 바꾸지 않는다.
   - `이 선 그대로`, `이 부분만`, `동그라미 친 곳`은 pixel-local edit 지시로 취급한다.
   - 사용자 마킹과 일반 생성 prompt가 충돌하면 사용자 마킹이 우선한다.

3. **국소수정 지시는 국소수정만 한다.**
   - `우측 아래 좌측 작은 그림만`처럼 영역이 특정되면 그 영역 외의 인물, 손, 발, 화살표, 텍스트, 레이아웃은 바꾸지 않는다.
   - 하나의 overlay 위치 오류를 고치기 위해 전체 infographic을 재생성하지 않는다.
   - 전체 재생성은 사용자가 명시적으로 요구하거나 원본 자체가 구조적으로 사용할 수 없을 때만 허용한다.

4. **수정 전후 대조 검수 후에만 PASS 후보로 올린다.**
   - 원본과 수정본을 나란히 비교한다.
   - 요청된 영역이 실제로 바뀌었는지 확인한다.
   - 요청하지 않은 영역이 변하지 않았는지 확인한다.
   - 해부학적 landmark와 힘/이동 방향이 임상 brief와 일치하는지 다시 확인한다.
   - 하나라도 불일치하면 Preview/승인 후보로 연결하지 않는다.

### Babinski 교정에서 확정된 예시
- 실패 원인: `외측`을 화면 좌우로 해석하고, 사용자가 표시한 한 영역만 고치라는 지시에도 전체 이미지를 반복 재생성함.
- 정답 처리: `발바닥 외측 뒤꿈치 → 외측 border → 제5족지 쪽`을 해부학적으로 잠그고, 사용자가 표시한 **우측 아래 좌측 작은 그림의 화살표만** 국소 수정.
- 이 사례는 앞으로 동일 유형의 시각교정에서 회귀 방지 기준으로 사용한다.
